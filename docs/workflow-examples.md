## Quick Start: New Project Setup

### Scenario
Setting up SDET Skills for a brand new project with no existing tests.

### Commands
```bash
# 1. Clone skill pack
git clone https://github.com/yourorg/sdet-skills.git ~/.claude/skills/sdet

# 2. Initialize project
mkdir my-project && cd my-project
cp ~/.claude/skills/sdet/sdet.config.yaml.example sdet.config.yaml

# 3. Create requirements
mkdir requirements
cat > requirements/auth.md << 'EOF'
# Authentication Requirements
## REQ-001: User Login
Users can login with email/password
- AC: Valid credentials → redirect to dashboard
- AC: Invalid credentials → show error message
- AC: Locked account → show lockout message
EOF

# 4. Run full pipeline
/sdet-orchestrate --workflow full --autoApprove

# 5. Review outputs
ls artifacts/
# test-cases/test-cases-<timestamp>.xlsx
# tests/ui/, tests/api/, tests/security/, etc.
```

### Expected Output
- Structured requirements in `artifacts/requirements/`
- Excel test cases in `artifacts/test-cases/`
- Automation code in `tests/`
- CI/CD pipeline in `.github/workflows/`

## Daily Development Workflow

### Scenario
Developer pushes code, runs quick validation before merge.

### Commands
```bash
# Quick validation (no requirement analysis)
/sdet-orchestrate --workflow quick --autoApprove

# Or individual skills
/sdet-validate --file ./artifacts/test-cases/latest.xlsx
/sdet-automate --type ui,api --framework playwright
/sdet-execute --type ui,api --parallel 4 --retry 1
/sdet-analyze-results --updateExcel true
```

### CI Integration
```yaml
# .github/workflows/quick-validation.yml
name: Quick Validation
on:
  pull_request:
    branches: [main]

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run SDET Quick Workflow
        run: npx sdet-orchestrate --workflow quick --autoApprove
```

## CI/CD Pipeline Execution

### Scenario
Full pipeline execution in CI with quality gates.

### Generated Pipeline (GitHub Actions)
```yaml
# .github/workflows/sdet-pipeline.yml (generated by /sdet-deploy)
name: SDET Full Pipeline

on:
  push:
    branches: [main]
  schedule:
    - cron: '0 2 * * *'  # Nightly

jobs:
  analyze:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npx sdet-analyze --source ./requirements
      - uses: actions/upload-artifact@v4
        with:
          name: requirements
          path: artifacts/requirements/

  generate:
    needs: analyze
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/download-artifact@v4
        with:
          name: requirements
          path: artifacts/requirements/
      - run: npx sdet-generate --template standard
      - uses: actions/upload-artifact@v4
        with:
          name: test-cases
          path: artifacts/test-cases/

  validate:
    needs: generate
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/download-artifact@v4
        with:
          name: test-cases
          path: artifacts/test-cases/
      - run: npx sdet-validate --strict true

  automate:
    needs: validate
    runs-on: ubuntu-latest
    strategy:
      matrix:
        type: [ui, api, security, performance, accessibility, contract]
    steps:
      - uses: actions/checkout@v4
      - run: npx sdet-automate --type ${{ matrix.type }}
      - uses: actions/upload-artifact@v4
        with:
          name: automation-${{ matrix.type }}
          path: tests/${{ matrix.type }}/

  execute:
    needs: automate
    runs-on: ubuntu-latest
    strategy:
      matrix:
        type: [ui, api, security, performance, accessibility, contract]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/download-artifact@v4
        with:
          name: automation-${{ matrix.type }}
          path: tests/${{ matrix.type }}/
      - run: npx sdet-execute --type ${{ matrix.type }} --parallel 4
      - uses: actions/upload-artifact@v4
        with:
          name: results-${{ matrix.type }}
          path: artifacts/results/${{ matrix.type }}/

  analyze-results:
    needs: execute
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/download-artifact@v4
        with:
          pattern: results-*
          path: artifacts/results/
      - run: npx sdet-analyze-results --updateExcel true --createDefects true
      - uses: actions/upload-artifact@v4
        with:
          name: updated-test-cases
          path: artifacts/test-cases/

  deploy:
    needs: analyze-results
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npx sdet-deploy --platform github-actions --qualityGates true
```

## Security Testing Workflow

### Scenario
Dedicated security testing pipeline for compliance.

### Commands
```bash
# Security-focused workflow
/sdet-orchestrate --workflow security --autoApprove

# Or manual execution
/sdet-analyze --source ./requirements --includeSecurity true
/sdet-generate --template security
/sdet-validate --strict true
/sdet-automate --type security --framework semgrep,zap,trivy
```

## Performance Testing Workflow

### Scenario
Load, stress, and soak testing for release validation.

### Commands
```bash
# Performance workflow
/sdet-orchestrate --workflow performance --autoApprove

# Individual load test types
/sdet-load --type load --tool k6 --vus 100 --duration 10m
/sdet-load --type stress --tool k6 --vus 500 --duration 15m
/sdet-load --type soak --tool k6 --vus 50 --duration 4h
/sdet-load --type spike --tool k6 --vus 1000 --duration 2m
/sdet-load --type breakpoint --tool k6 --maxVus 2000

# Profiling
/sdet-perf-profile --profiler async-profiler --target cpu --duration 5m
/sdet-perf-profile --profiler async-profiler --target memory --duration 10m
```

### k6 Test Configuration
```javascript
// Generated: tests/performance/k6/load-test.js
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  stages: [
    { duration: '2m', target: 100 },  // Ramp up
    { duration: '5m', target: 100 },  // Stay
    { duration: '2m', target: 0 },    // Ramp down
  ],
  thresholds: {
    http_req_duration: ['p(95)<500', 'p(99)<1000'],
    http_req_failed: ['rate<0.01'],
    checks: ['rate>0.99'],
  },
};

export default function () {
  const res = http.get('https://api.example.com/health');
  check(res, { 'status 200': (r) => r.status === 200 });
  sleep(1);
}
```

## Legacy Migration Workflow

### Scenario
Migrate Selenium/JUnit4 tests to Playwright/JUnit5.

### Commands
```bash
# Full migration workflow
/sdet-orchestrate --workflow migration --autoApprove

# Step by step
/sdet-analyze --source ./legacy/selenium-tests/ --format json
/sdet-migrate --from selenium --to playwright --mode hybrid
/sdet-migrate --from junit4 --to junit5 --mode translate
/sdet-validate --file ./modern/playwright-tests/ --compare ./legacy/selenium-tests/
/sdet-execute --compareMode true \
  --legacyCmd "mvn test" \
  --modernCmd "npx playwright test"
/sdet-report --type migration --format html --output migration-report.html
```

### Migration Modes
| Mode | Use Case |
|------|----------|
| `translate` | Simple, mechanical conversions (JUnit 4→5) |
| `rewrite` | Complex logic needing better idioms |
| `hybrid` | Translate + LLM polish (recommended) |
| `validate` | Run both, compare results only |

## Monorepo Affected Testing

### Scenario
Only test changed packages in a Turborepo monorepo.

### Commands
```bash
# Affected packages only
/sdet-orchestrate --workflow affected-only --autoApprove --since main

# With Turbo
turbo run sdet:analyze sdet:generate sdet:validate sdet:automate sdet:execute sdet:analyze-results

# Package-specific
pnpm --filter frontend sdet:orchestrate --workflow frontend-only
pnpm --filter backend sdet:orchestrate --workflow backend-only
```

## Exploratory Testing Session

### Scenario
Structured exploratory testing with charter-based approach.

### Commands
```bash
# Start session
/sdet-explore --charter "Explore checkout flow for payment failures, 60min" --technique sbet

# During session: notes auto-captured
# Debrief
/sdet-explore --charter "Debrief: checkout payment failures" --technique sbet --debrief

# Generate report
/sdet-report --type technical --format html --include explore
```

### Session Template (SBET)
```
Charter: Explore checkout flow for payment failures
Timebox: 60 minutes
Tester: Jane Doe
Date: 2026-10-22

Areas Explored:
- [x] Valid payment → success
- [x] Invalid card → decline
- [x] Expired card → decline
- [x] Insufficient funds → decline
- [x] Network timeout → retry
- [ ] 3D Secure challenge
- [ ] Partial refund scenario

Bugs Found:
- BUG-001: Timeout not handled gracefully (Critical)
- BUG-002: Error message unclear for expired card (Medium)

Obstacles:
- Test data setup slow
- Staging env unstable

Outlook:
- Add 3D Secure test cases
- Improve test data seeding
```

## Flaky Test Remediation

### Scenario
Detect, quarantine, and fix flaky tests.

### Commands
```bash
# Full flake workflow
/sdet-flake --window 30 --action all

# Step by step
/sdet-flake --window 30 --action detect
/sdet-flake --window 30 --action quarantine
/sdet-flake --window 30 --action fix --mode suggest
/sdet-flake --window 30 --action report

# Auto-heal specific failures
/sdet-autoheal --target selectors --mode suggest
/sdet-autoheal --target assertions --mode suggest
/sdet-autoheal --target waits --mode auto-apply
```

## Test Migration Workflow

### Scenario
Migrate from Cypress to Playwright across organization.

### Commands
```bash
# Assess migration
/sdet-migrate --from cypress --to playwright --mode validate

# Execute migration
/sdet-migrate --from cypress --to playwright --mode hybrid

# Validate
/sdet-validate --file ./modern/playwright-tests/ --compare ./legacy/cypress-tests/
/sdet-execute --compareMode true \
  --legacyCmd "npx cypress run" \
  --modernCmd "npx playwright test"
```

### Migration Pairs Supported
| From | To | Mode Support |
|------|-----|--------------|
| Cypress | Playwright | translate, rewrite, hybrid, validate |
| Selenium | Playwright | translate, rewrite, hybrid, validate |
| Selenium | Cypress | translate, rewrite, hybrid |
| JUnit 4 | JUnit 5 | translate, rewrite |
| JUnit 4 | TestNG | translate, rewrite |
| TestNG | JUnit 5 | translate, rewrite |
| Postman | Pactum | rewrite, hybrid |
| Postman | k6 | rewrite, hybrid |
| SoapUI | REST Assured | hybrid |

## Advanced: Custom Workflow Composition

### Creating Custom Workflows
```javascript
// scripts/checkpoint-helpers.js - Add custom workflow
customSecurityPerf: {
  name: 'Security + Performance',
  stages: [
    { id: 'analyze', skills: ['analyze'] },
    { id: 'generate-security', skills: ['generate'], args: { template: 'security' } },
    { id: 'generate-perf', skills: ['generate'], args: { template: 'performance' } },
    { id: 'validate', skills: ['validate'] },
    { id: 'automate-security', skills: ['automate'], args: { type: 'security' } },
    { id: 'automate-perf', skills: ['automate'], args: { type: 'performance' } },
    { id: 'execute-security', skills: ['execute'], args: { type: 'security' } },
    { id: 'execute-perf', skills: ['execute'], args: { type: 'performance' } },
    { id: 'analyze-results', skills: ['analyze-results'] },
    { id: 'report', skills: ['report'], args: { type: 'technical' } }
  ]
}
```

### Run Custom Workflow
```bash
/sdet-orchestrate --workflow customSecurityPerf --autoApprove
```

## Best Practices Summary

| Practice | Why | How |
|----------|-----|-----|
| Use workflows | Consistency, reproducibility | `/sdet-orchestrate --workflow <name>` |
| Enable checkpoints | Resume after failure | Auto-enabled in orchestrator |
| Version control artifacts | Traceability | Commit `artifacts/` or use artifact storage |
| Run quick in PR, full nightly | Fast feedback + depth | CI config with two pipelines |
| Monitor flake rate | Maintain velocity | `/sdet-flake` weekly |
| Update baselines | Prevent drift | `/sdet-autoheal` + visual approval |
| Document decisions | Knowledge retention | `/sdet-dashboard` living docs |
